# web

Minimal Next.js frontend for the `staking_vault` devnet deployment. Connect Phantom or Solflare
(devnet), stake TEST, watch rewards accrue, claim, unstake.

## Setup

```bash
cp .env.example .env.local
```

Fill in `.env.local` from `docs/DEPLOYMENT.md` (generated by `yarn setup:devnet` at the repo
root):

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_RPC_URL` | Devnet RPC endpoint, e.g. `https://api.devnet.solana.com` |
| `NEXT_PUBLIC_PROGRAM_ID` | The deployed program ID |
| `NEXT_PUBLIC_STAKE_MINT` | The TEST stake mint address |

If any of these are missing or invalid, the app shows a red banner listing what's wrong instead
of a broken page.

## Develop

```bash
yarn workspace web dev
```

Open http://localhost:3000, set your wallet to Devnet, and connect. If you have no TEST balance
yet, the app shows the stake mint address and the `setup:devnet -- --mint-to` command to fund
yourself.

## Build

```bash
yarn workspace web build
yarn workspace web start
```

## How it's put together

- **Wallet**: `@solana/wallet-adapter-react` + `-react-ui` + `-wallets` (Phantom, Solflare). The
  provider tree (`app/wallet-providers.tsx`) is loaded via `next/dynamic(..., { ssr: false })`
  from `app/providers.tsx` since wallet adapters touch `window` on mount and must never run
  server-side.
- **Reads**: `app/page.tsx` fetches the pool, the caller's stake account, and token balances
  once on mount/wallet-change and again after each transaction confirms — no polling interval
  hits the RPC.
- **Claimable ticking**: the displayed claimable-rewards number advances every second purely by
  re-running the SDK's `claimableRewards()` math against the last-fetched snapshot with the
  current clock time (`lib/format.ts` / `@staking-vault/sdk`'s `math.ts`) — not by re-fetching.
- **Transactions**: every stake/unstake/claim runs through `components/TxToast.tsx`, which shows
  a signing → sent → confirmed/failed toast with a SolanaFM link.
